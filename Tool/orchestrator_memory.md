# Video Orchestrator Memory

- Default to silent video unless the user explicitly requests generated audio.
- Never draft prompts or submit Veo generation without the corresponding explicit user approval.
- Use one text-planning request per batch, one video per approved scene, sequential execution, and no automatic retries.
- Preserve immutable character and product descriptions across every applicable scene.
- Accept scripts in any language; compile final Veo prompts in concise English.
- Use Codex-generated images as optional Veo subject references. Treat requested timestamps as approximate generation targets, not frame-exact editing.
- Default to `veo-3.1-fast-generate-001`, 720p, with Agent Platform promotional-credit billing.
- Expose one shared script-to-video workflow to ChatGPT/Codex and Claude Code through `agent-video.mjs`; keep project state and manifests interchangeable between agents.
- In image-to-video prompts, describe the start frame's pose exactly and lock it ("palms stay joined above her head for the entire clip"); never add loose-hair-in-wind phrasing, which Veo renders as detached strands floating above the head. A pose word that contradicts the start frame makes Veo move the subject to match the words.
- `gemini-2.5-flash-image` on the studio's original Cloud project returned 429 after roughly 15 rapid calls; pace batches at about 45s between calls.
- `gemini-2.5-flash-image` letterboxes vertical frames (landscape scene inside blurred or flat bands) when prompts say "keep the upper X% and lower Y% quiet for captions". Instead require the scene to fill the canvas edge to edge with no borders, bands, letterboxing or inset panels, and let sky/ground run calm to the edges. Its "9:16" output is 768x1344; center-crop to 756x1344 for exact 9:16.
- In a reference-mode Veo clip, gods described only as "in the background" came back as identical grey duplicates. Keep secondary deities out of frame or supply them through keyframes.
- For first+last interpolation, generate the end frame with the start frame attached; image-model end frames can still drift environment details (platform shape, trees), so review pairs before paying for video. With `gemini-2.5-flash-image`, re-sending the full start prompt with only the change clauses swapped returned near-copies of the start frame (2 of 2). A short edit instruction ("Edit the supplied image. Keep ... The only change: ...") delivered a simple gesture change (elder steps back, knot tied), but not people grabbing someone: it dropped a character and shifted framing instead. Let Veo carry physical-contact actions from a first frame.
- A culture anchor naming earthly architecture (pagodas, brick, carved windows) pulls that architecture into heaven or other non-earthly scenes. Omit the anchor for those shots and give the realm its own "Never:" line.
- A rider-on-elephant "descending through cloud above the city" prompt with the city described in detail came back as a colossus standing in the city square. State the altitude and scale outright: the city tiny and far below, no ground-level people, open sky around the animal.
- One change per image edit. An edit combining "make the rope thinner" with "replace rooftop tanks" ignored the rope. It also replaced the tanks with another modern rooftop (concrete and a railing); name the period-correct replacement concretely.
- For multi-character keyframes with `gemini-2.5-flash-image` (max 3 refs), an ffmpeg-hstacked cast-lineup strip plus a location plate holds faces and rooms well. But attaching the previous keyframe as a continuity ref often makes the model clone that composition, dropping the newly named character or repeating the shot (about 6 of 44 frames). Attach a previous frame only for deliberate mirrors, and review for near-duplicates.
- Portrait references sometimes come back with people in the background despite a "plain backdrop" prompt; crop to the subject before using them as refs, or those people leak into keyframes.
- Editing a reference to shift skin tone a lot (dark to fair) with `gemini-2.5-flash-image` drifts identity toward European features and hair. Regenerate from updated canon text instead, and name the ethnicity explicitly ("light-skinned Indian tone, jet-black hair") plus "Never: European features". Small edits (removing a prop or hair ornament) on a kept reference work cleanly.
- Veo first+last interpolation invents a source for a stream of liquid or light that isn't clearly visible leaving its origin. In a milking clip it added a second cow head at the frame edge, pouring milk from its mouth. Lock the camera (no push-in), keep the origin (teats) in both frames, and say "no additional animals or heads enter the frame".
- A Veo first+last pair that transforms a goddess into an animal works well when both keyframes share a light spiral: the light becomes a column, hides the figure, and clears to reveal the new form. Confirmed again for god to human disguise (Indra Jatra, 2026-09-15). Build the second keyframe as an edit of the first, with the target identity ref attached; a text-generated pair came back at different positions and scales. The edit swapped the costume but kept the light column, so plan the prompt around lingering light.
- For a "divine but not a statue" look, never write "gold sheen" or "lit from within" into skin: `gemini-2.5-flash-image` gilds the whole body. Attach a natural-skin reference and put divinity in the halo, eyes, light and motes. A skin-only edit could not remove existing gilding.
- `gemini-2.5-flash-image` still renders readable number plates, tank badges and sewing-machine decals despite "no number plates, no logos" (Vishwakarma Puja stills, 2026-09-15: 1 readable plate on a front-facing scooter, pseudo-lettering on 3 of 18 frames). Hide plates by framing (garland over plate, side or rear angle) instead of relying on the negative line.
- A "welder lowers the face shield" pose came back with the shield raised above the face while the arc burned: the image model catches the gesture mid-way. For safety beats, state the finished safe state ("shield fully down covering the face while welding").
- `veo-3.1-fast-generate-001` rejects subject-reference (reference_to_video) jobs unless the duration is 8 s. It returns "Unsupported output video duration 6 seconds, supported durations are [8]" after submission (Vishwakarma Puja, 2026-09-15: 2 of 3 scenes failed). Set duration 8 for any scene with `subject_reference` assets.
- A 9:16 text-to-video Veo clip (no start image) came back letterboxed: 720x1280 file with a 720x1052 picture and 114 px black bars top and bottom. Run `cropdetect` on every clip; fix with crop 592:1052:64:114 then scale to 720x1280, or start from a full-bleed 9:16 keyframe to avoid bars. Starting from a keyframe worked: 2 of 2 image-to-video clips came back full-frame, with the look of a Vishwakarma rendered from a reference image intact.
- An image-to-video "hammer strikes a glowing disc" prompt produced a white flash lasting about 0.8 s that almost hides the figure. Write "a small controlled burst of sparks" if the subject must stay readable.
- Nepali puja "रातो-सेतो ध्वजा" (dhwaja) means bunches of long, narrow, loose red and white cloth ribbons knotted at one end and hanging as separate strips (tied to machines, mirrors, trees). Never write "flag": `gemini-2.5-flash-image` renders rectangular red-over-white flags on sticks that read as the Indonesian national flag (user correction, 2026-09-15). Describe the strips outright and add "Never rectangular or triangular flags, pennants, national flags, or flags on sticks".
- For supplied logos, use image-to-video with the logo as the starting image. Never ask the model to generate or reconstruct readable words: prohibit letters, captions, slogans, signage, subtitles, and synthetic wordmarks because wording may be altered.
- Never name a human scale in the positive half of a prompt for something that must NOT be a person. "A faint disturbance in the air about the height and width of a standing adult" returned a solid opaque human silhouette from `gemini-2.5-flash-image`, defeating a fourteen-item "Never a person, body, face, silhouette, sheet, robe, skull..." line in the same prompt (Pitri/Preta/Vayu, 2026-09-16). The front-loaded description wins over any length of trailing negative. Two fixes both work: anchor the scale to an object ("a hand's width across, floor to lintel height") instead of a body, and — when the brief does want a human shape — make it a property of a SHADOW ON A SURFACE rather than of a thing standing in the room. "One dark shadow of a standing figure cast flat across the wall and floor, with nothing casting it, darkening the plaster without hiding it, bending where wall meets floor, the floor between the light and the wall empty" returned exactly that, and read as eerie rather than as horror. The model may move the shadow onto a better surface than the one named (it chose the inner face of the open door, where no caster is possible at all) — accept that.
- A flame instructed to lean renders perfectly vertical when the instruction sits in a subordinate clause and the flame is not the frame's anchor subject (Pitri/Preta/Vayu, 2026-09-16). Give the lean a drawable consequence in the same sentence — "its teardrop flame pulled over hard to the left, bent well off vertical with its thread of soot bending the same way" — and it renders, soot trail included.
- `server.mjs` silently truncates image prompts at 4000 characters (`cleanText(req.body.prompt, 4000)`). Canon blocks plus a culture anchor plus a constraint block reach that ceiling fast, so run a free length check before any paid batch; a truncated prompt loses its constraint block first, because constraints go last.
- `gemini-2.5-flash-image` occasionally returns a candidate with NO image part, `finishReason: STOP`, no safety ratings and no prompt feedback — a transient empty response, not a refusal (Pitri/Preta/Vayu, 2026-09-16: frame 01 failed, the identical prompt with the identical reference attached succeeded on the next call). `server.mjs:55` reports this as "Model completed without a downloadable image" and discards the reason, so the log cannot distinguish it from a real block. Diagnose by re-issuing the same call once through a path that prints `finishReason`/`safetyRatings`/text parts before changing anything; rewriting the prompt is the expensive wrong move.
- `veo-3.1-fast-generate-001` straightens a deliberately leaning flame over the clip: an image-to-video start frame whose flame is bent hard sideways returns to vertical by the end (Pitri/Preta/Vayu, 2026-09-16: 2 of 2 lamp clips). The model normalises toward physical default and undoes a non-physical start state. Do not describe the lean as a state; give the draught a continuous cause for the whole clip and name the end state outright ("the flame never returns to upright").
- `veo-3.1-fast-generate-001` adds a slow drift to the framing even when the prompt says "the camera is locked off and does not move at all" (Pitri/Preta/Vayu, 2026-09-16: 4 of 4 clips drifted right). Treat a locked-off frame as unachievable by instruction; stabilise or crop in post if framing must hold.
- `/api/quick/video` returns `{file: "..."}` (singular) while `/api/quick/image` returns `{files: [...]}`. A runner that checks only `files` will throw on a successful video and look like a generation failure — check `output/quick/` before concluding anything failed or paying to regenerate.
- Image-to-video from a full-bleed 9:16 keyframe still adds a real 10 px black bar top and bottom on `veo-3.1-fast-generate-001` (much smaller than the 114 px text-to-video bars, but present). Verify by extracting the edge strip rather than trusting `cropdetect` alone; fix with `crop=720:1260:0:10,scale=720:1280`.
- A prompt whose scene is abstract (cloud, mist, light, air) can be overridden by its own culture anchor: `gemini-2.5-flash-image` rendered a household shrine interior — niche, lamp, vermilion stone, leaf plates — for a dawn-valley landscape prompt, because the anchor's ritual-object list was the only concrete thing available (Pitri/Preta/Vayu, 2026-09-16). The most concrete noun wins wherever it sits in the prompt. Give an abstract scene concrete nouns of its own and add "this is a landscape photograph with no building, no room, no lamp, no offering and no ritual object anywhere in the frame".
- Nepali kul devata are overwhelmingly aniconic and the forms differ by lineage, so "show a kuldevata" should render a FORM, not a generic idol: an uncarved vermilion-built slab, a cluster of iron tridents with red cloth on the shafts (point-up, not driven point-down), an oiled river stone in tree roots, a rain-worn serpent slab, a drystone than with a slate roof and a dark opening, a hand-beaten copper face plate on red cloth. All six rendered cleanly first pass. Do not name the deity or attach it to a caste unless the script does.
- A shadow with no caster CAN be made to walk in `veo-3.1-fast-generate-001` image-to-video, provided the start frame's shadow lies at an angle no camera could produce (Pitri/Preta/Vayu, 2026-09-16: 2 of 2 worked — a shadow crossing a courtyard, a shadow on a wall sliding into a doorway and vanishing — with "no person, no feet, no body appears at any moment" stated in the action sentence; no caster was ever added). But when the start frame reads as the PHOTOGRAPHER'S OWN SHADOW (sun behind camera, figure square to lens, shadow pointing straight away), Veo keeps the shadow in place and drifts the camera instead (1 of 1). For a walking shadow, put the sun to the side or ahead in the keyframe, or supply an end frame.
- `veo-3.1-fast-generate-001` dropped a small child from a family group about 1.3 s into a 4 s clip (Pitri/Preta/Vayu, 2026-09-16). Check small secondary figures across the clip, not just at the ends; trim the head of the clip if the disappearance is early.
- A 20-scene quick-image batch (Kirat/Chyasal history explainer, 2026-09-23) paced at only 12s between `/api/quick/image` calls on `gemini-2.5-flash-image` hit `429 RESOURCE_EXHAUSTED` starting at roughly the 8th consecutive call, well before the ~15-rapid-call ceiling noted earlier in this log — only 6 of 20 calls succeeded, the rest split between explicit 429s and the transient "completed without a downloadable image" empty response. The per-minute quota is tighter than call-count alone suggests; pace batches above ~12 scenes at 45-60s between calls, and treat both failure types as retryable-on-user-approval only (never automatically) since the transient empty response has previously succeeded on an identical immediate retry while a 429 needs an actual cooldown, not just a retry.
- Same batch, continued: 5 specific beats (a scribe/elder speaking to a group, a lamp-lighting ceremony, an aged-settlement landscape, a calm sky) failed with the "completed without a downloadable image" empty response 3 to 4 times EACH across separate retry rounds at 55s pacing, including after rewording two of the prompts to remove any writing/text-adjacent language. 100% reproducible failure across unrelated prompt content is not the transient single-miss case documented earlier in this log — that one flipped to success on the very next identical call. When a beat fails identically 3+ times in a row despite reasonable pacing and prompt variation, stop retrying (it is very likely a session-level or quota-level service degradation, not the prompt or a one-off glitch) and either wait a longer cooldown (many minutes, not seconds) before trying again, or move on and report it as a genuine outage rather than spending further paid calls.
- ROOT CAUSE of the two Kirat/Chyasal batch notes above, found 2026-09-23 by calling Vertex directly instead of through `server.mjs`: the phrase **"no watermark"** in a negative line makes Google's safety classifier return `promptFeedback.blockReason: "SAFETY"` with `blockReasonMessage: "The prompt is blocked due to requesting to remove watermarks"`. No candidate is returned at all, so `generateOneImage` (`server.mjs:54`) finds no `inlineData` part and throws the generic "Model completed without a downloadable image." The failure is therefore a hard prompt block, NOT a transient empty response and NOT quota degradation — which is why the same beats failed identically 3-4 times each and why no cooldown ever helped. The 10 successes in the same batch were the classifier scoring the identical line inconsistently, which made it look random. Never write "no watermark", "remove watermark" or "no readable wordmarks" into a prompt; use `No text, no captions, no signage, no lettering and no logos anywhere in the frame.` instead. Diagnose any "completed without a downloadable image" by printing `promptFeedback` from a direct `generateContent` call BEFORE assuming an outage — `server.mjs` discards it and the two notes above drew the wrong conclusion from that missing field alone.
- Asking for `plain undyed cloth banners` on a Nepali historical shot still returned the modern Nepali NATIONAL flag (crimson double-pennon with white sun and moon) on `gemini-2.5-flash-image` (Kirat/Chyasal, 2026-09-23). This extends the dhwaja note above: the model reaches for the country's real flag for ANY flag-shaped object once a nationality is implied by the setting, even when the prompt says plain and undyed. If a period shot does not need cloth on a pole, ban the whole category outright: "no flags, no banners, no pennants, no poles and no national flags of any kind anywhere in the frame".
- `gemini-2.5-flash-image` cannot render a specific finger count. "Holding up eight fingers" returned an open five-finger palm; "both hands raised showing eight extended fingers with both thumbs folded down" returned two fully open palms (ten) — 2 of 2 wrong (Kirat/Chyasal beat09, 2026-09-23). For a beat whose meaning IS a number, do not count on hands at all; lay the number out as discrete countable objects instead ("exactly eight small clay lamps in one clear straight row, evenly spaced and easy to count") and verify the count in the returned frame before accepting it.
- Letterboxing recurs specifically on epic WIDE-VISTA beats ("looking out over the valley far below", "wide epic golden-hour"), because the described composition is inherently 16:9 and the model honours the composition over the requested aspect ratio (Kirat/Chyasal beat07, 2026-09-23: 2 of 2 vista attempts letterboxed, the second one severely — a 16:9 picture centred in the 9:16 canvas). A negative-style clause alone is NOT enough: "The scene fills the entire vertical frame edge to edge, with no borders, no black bars, no letterboxing and no inset panels" still letterboxed on the very next call. What fixed it in one attempt was describing a composition that can only be vertical — name the portrait orientation and stack the content in three bands top to bottom: "Tall vertical portrait composition, shot in portrait orientation with the frame much taller than it is wide. The composition stacks in three bands from top to bottom: sky across the top, the valley receding in the middle, and the parapet with the figures across the bottom." Give the model a vertical composition to draw, rather than forbidding a horizontal one.
- Parallel batches on `gemini-2.5-flash-image` (Sati/Bhim Malla, 2026-09-24): three batches of 5 concurrent calls with 45 s gaps hit one 429 in the third batch, and a follow-up batch of 4 fired about a minute later hit another 429. So 5 concurrent calls is fine, but back-to-back batches exhaust the per-minute quota. Leave at least 90 s between 5-call batches.
- `gemini-2.5-flash-image` defaults to WESTERN visual tropes for generic prop/architecture nouns on a Nepali historical shot unless the prompt names the actual regional form (Chyasal supplementary batch, 2026-09-24, 15-frame pass): "round shields" came back Viking (painted heraldic animal roundels, metal boss); "old stone gateway" came back a European Tudor half-timber town square; "brick house under construction" came back a Roman/Mediterranean villa (belted tunics, terracotta barrel tiles) even after fixing an unrelated letterbox on the same frame. Each fixed cleanly only once the prompt named the real regional form and added an explicit negative: plain undecorated wood-and-hide shields ("never Viking, never a painted heraldic animal or star"), a Newar brick gateway with a tiered pagoda roof ("never European, never Tudor half-timber, never Gothic stone"), Nepali jhingati overlapping clay tiles and workers in wrapped dhoti cloth with no belts ("never Roman, never Mediterranean, never a European villa, never terracotta barrel tiles"). Generic nouns for props, buildings and clothing need a named regional form and an explicit "never <the wrong culture>" line every time, not just once per prompt family.
- Letterboxing is not limited to literal wide-vista compositions (contra the note above): a CLOSE-UP window-frame shot with a background scene visible through the opening also letterboxed on `gemini-2.5-flash-image` (Chyasal supplementary batch, 2026-09-24) — any composition implying depth/background scenery behind a foreground frame seems to trigger it. Add the "full-bleed vertical 9:16 ... scenery filling every edge ... no letterbox, no black bars" line proactively to any shot with implied depth, not only after a letterboxed frame comes back.
- An all-caps name label at the start of an object canon block ("THE OKHAL STONE: a huge boulder...") was painted onto the object as carved/printed text on `gemini-2.5-flash-image` (Okhaldhunga pack, 2026-09-24, 1 of 1), even with the no-text NEG line. Open object canon blocks with plain description ("The stone is a single huge..."), never a capitalised title; character-name labels (BHIM MALLA, ...) did not cause this.
- Okhaldhunga pack (2026-09-24): a 40-frame run at `5 90` lost 22 of 40 calls to 429, the `2 45` re-run lost 10 of 22 more, and `1 60` then cleared all 10. Once the quota is exhausted, drop straight to one call per 60 s.
